# Improve title-screen font rendering ("MULTIPLAY" patch)

## Diagnosis (from code analysis, no emulator run needed)

The font is `Client::patchTitleMenu()` in `client/fzvs_client.cpp:160-218` (part of the current uncommitted change). It hand-rasterizes a 10-glyph, 7-row bitmap font into an 80×16 mask (2× vertical pixel doubling), adds a 1px outline via 3×3 dilation (color 5 outline / color 2 fill), encodes SNES 4bpp tiles, and writes 5 tiles per row (40px wide) to ROM `0x67800` / `0x67a00`.

The "kerning" problem: `drawWord("MULTIPLAY",0,40,0)` uses **spacing = 0** and glyph widths total 38px, so adjacent letters share edges — M|U and U|L have full-height columns touching (solid 2px bars), T|I, I|P, A|Y partially merge. Only 2px of slack exist in the 40px region; real 1px gaps between all 9 pairs would need ~47px, so a spacing fix alone cannot fit — the design must change (narrower/better glyphs, wider area, or different layout).

The patch is applied in-memory at runtime when the client attaches to a room (`attach()` → `patchTitleMenu()`), so the visual gate requires a running fzvs server + attached emulator.

### 2. Inspect original art (decides the design)
- Decode ROM bytes around `0x67800`–`0x67c00` (via `rom.read` + local decode): see the original GRAND PRIX glyph style, palette indices, and whether a fuller title-font atlas (M, U, L, T, Y, …) exists nearby in ROM.
- Read VRAM tilemap + CGRAM on the title screen to learn: which tile indices the menu sprites map to, whether the 6th tile per row (`0x67800+5*32`, `0x67a00+5*32`) is free, and what palette indices 2/5 actually are.
- Screenshot the pristine title screen (before attach) to see the original layout.

### 3. Implement the improved font in `patchTitleMenu()`
- **Preferred:** if the original title-font glyphs are found, rebuild MULTIPLAY from authentic shapes with correct spacing; layout (one or two rows) follows the original metrics.
- **Fallback:** redraw the glyph set — crisper 7-row shapes, proper side bearings, per-pair kerning table, 1px inter-letter gaps; widen to 6 tiles/row only if step 2 proved those tiles unused (PRACTICE shares tiles $126–$129 — do not touch).
- Keep `titleOriginals` restore bookkeeping and the sprite-hide logic in `frame()` unchanged.
- Sanity-check the rasterizer output offline first (small ASCII/PNG preview script) to minimize emulator rebuild cycles.

### 4. Tests
- Update `tests/client_lifecycle_test.cpp:26-30` tile-range assertions to the new region; run `make test-client-lifecycle`, then `make test`.

### 5. Visual gate ("after") + regression check
- `make ares` (incremental), relaunch, attach, screenshot the new title; compare against baseline. Also verify the PRACTICE menu entry renders unaffected (screenshot or tilemap read).
- Iterate pixel tweaks (each cycle = rebuild + relaunch + screenshot) until the font reads cleanly.
